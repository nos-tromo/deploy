# workbench v0.3.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the new chat app `ghostwriter` a third workbench caller. It gets the eight workspace tools over the MCP door, and upload, view, list and a chat delete over REST. Every path it names is confined to the request's chat, each csv or xlsx output carries a table preview read by the executor, and its limits and audit are its own. Open WebUI's terminal door and docint's inline door stay as they are.

**Architecture:** Ghostwriter is the first caller that comes in through the MCP door with workspace files (`Caller.confined`):
- **The gate.** `KeyGate` lets its key reach `/mcp` and four file routes.
- **The chat boundary.** Its principal carries `confined`, so `Store._locate` answers `NotFound` for any path outside `X-Session-Id`'s chat.
- **The tools.** `workbench/api/tools_mcp.py` serves the eight workspace routes on MCP by calling the route functions themselves. It swaps in a bound audit log (purpose, request id, the purpose rule), the caller's limits (`CallJobs` over `CallLimits`) and a settings copy whose wall leaves the previews their time. It lists the files a call wrote as `outputs`.
- **The preview.** The executor reads a csv or xlsx output's header and five rows inside the job (`workbench/executor/preview.py`). The preview rides on `OutputFile` to the api, which checks its shape and parses no file.

**Tech Stack:** as v0.2.0 (Python 3.12, uv, FastAPI, pydantic v2, SQLite; openpyxl in the executor). The `mcp` SDK in the dev group runs the conformance test. No new dependency.

**Spec:** deploy's `docs/superpowers/specs/2026-11-16-ghostwriter-design.md`.
- §6.4 is binding, with §2, §3, §5 and §9.
- The shared contract's workbench lines are copied verbatim under Global Constraints. They bind this plan and its two sibling plans (Ghostwriter app, the federation).
- Where this plan is silent, workbench's v0.2.0 design and plan still hold (`docs/superpowers/specs/2026-11-15-v2-mcp-docint-design.md`, `docs/superpowers/plans/2026-11-15-workbench-v2.md`).
- Every path below is relative to the workbench repo root.

## Global Constraints

**From the shared contract, verbatim:**

- **workbench:** the caller name is `ghostwriter`.
- **workbench side:**
  - `GHOSTWRITER_WORKBENCH_KEY`. Empty means the caller is off. A set key must be at least 32 characters and differ from the other callers' keys.
  - `GHOSTWRITER_WORKBENCH_TOOLS`, default `list_files,read_document,search_files,run_python,inspect_template,fill_template,write_table,write_document`.
  - `GHOSTWRITER_WORKBENCH_WALL_S`, default 120.
  - `GHOSTWRITER_WORKBENCH_SLOTS`, default 2.
- `WORKBENCH_API_KEY` (the same value as workbench's `GHOSTWRITER_WORKBENCH_KEY`, generated by env-sync);
- `WORKBENCH_RETENTION_DAYS` (default 7, the same value as workbench's, shared by env-sync);
- `X-User-Id` = the HMAC-SHA256 pseudonym of the user, keyed with `WORKBENCH_API_KEY`, over `workbench-user/v1`, a NUL byte and the owner name, as 64 hex digits.
- `X-Session-Id` = the same HMAC over `workbench-session/v1`, a NUL byte and the chat's uuid. This is the chat's folder in workbench.
- These are the same constructions docint uses (`docint/utils/workbench_client.py`). No edge user name and no chat uuid ever reach workbench.
- `X-Audit-Purpose` is forwarded. Without a stated purpose, the system reason is `ghostwriter chat`.
- `X-Request-ID` is forwarded.
- **`POST /mcp`:** the workspace tools as MCP tools (revision 2026-07-28), on the caller's list.
  - The tool result's `structuredContent` is the tool's REST output model, plus `outputs`.
  - `outputs` is a list of `{id, path, name, mime, size, preview}` for every file the call wrote (`run_python` out/ files, `fill_template`, `write_table`, `write_document`).
  - `preview` is set only for csv and xlsx outputs: `{columns: [str], rows: [[str]], row_count: int | null, truncated: bool}`. It holds the header plus at most 5 rows and 20 columns, with cells cut to 100 characters. The executor reads it; the api never parses a file.
  - The result never carries file bytes.
- **`POST /files/upload?directory=/workspace/<X-Session-Id>`:**
  - multipart field `file`, at most 50 MB;
  - answers `{path, size, id}` (add `id` if missing).
  - For the `ghostwriter` caller, the directory's chat must equal `X-Session-Id`, or the answer is `404 {"detail":"not found"}`.
- **`GET /files/view?path=/workspace/<X-Session-Id>/<name>`:** for the `ghostwriter` caller, only paths inside the request's chat. Anything else gets the 404.
- **`DELETE /files/chat`:** a new route, not a tool. It deletes the chat named by `X-Session-Id`; `default` is refused with 400. It answers `200 {"deleted": <count>}`, and also when the chat holds nothing.
  - Its audit event is `delete` / `chat.delete`, by id, written first.
  - Late outputs of jobs still running in that chat are refused.
- **The chat boundary for the `ghostwriter` caller.** Every path-taking tool and file route is confined to the request's chat (`X-Session-Id`). Open WebUI's caller keeps v0.2.0 behaviour.
- **KeyGate.** The `ghostwriter` key reaches only `/mcp`, `/files/upload`, `/files/view`, `/files/list` and `/files/chat`. Everything else gets the 404.
- workbench files: 7 days (unchanged).
- Ghostwriter tool contents and previews: emptied after `WORKBENCH_RETENTION_DAYS`.
- **Versions:** workbench 0.2.0 → 0.3.0; Ghostwriter 0.1.0 (new repo `nos-tromo/ghostwriter`).
- **Order:**
  1. deploy env-sync rows and ADR 0007;
  2. obs-plane;
  3. workbench v0.3.0;

## Review Focus

1. **File names users really have.** For example `Übersicht März #1.xlsx`: spaces, umlauts, `#` and `%`. Each is uploaded, viewed by its percent-encoded path, read by a tool, and written back as an output. Expected: the name comes back exactly in `path` and `name`, and the view answers 200 with the bytes. Tests: Task 2 `test_a_name_with_spaces_umlauts_and_a_hash_round_trips` and Task 6 `test_output_names_come_back_as_written`.
2. **The model calls `display_file` out of habit.** The workspace tools' descriptions tell Open WebUI's model to show files with it. Expected: "display_file" appears nowhere in Ghostwriter's `tools/list`, and a call of it is `-32602` "unknown tool", never a 500. Test: Task 6 `test_display_file_is_nowhere_in_ghostwriters_tools`.
3. **A name the chat already holds.** The model writes `counts.csv` in two turns. Expected: the second comes back as `counts (1).csv` in `name` and `path`, with its own id and its own preview. Test: Task 6 `test_a_taken_name_comes_back_numbered_with_its_own_preview`.
4. **CSV as German Excel writes it.** That means semicolons, a BOM, or Latin-1 "Müller". Expected: the cells are split on `;`, the BOM is gone from the first column, and a Latin-1 file still gets a preview, with U+FFFD for the byte. Test: Task 4 `test_a_semicolon_csv_with_a_bom_and_a_latin1_one_preview`.
5. **A table too big to count.** For example 200 000 rows, or 30 columns with long cells. Expected: the header and 5 rows come back, `row_count` is `null` and `truncated` is true. The job still ends `ok` with its outputs kept: the preview never costs the file. Tests: Task 4 `test_counting_that_runs_out_of_time_keeps_the_rows_with_no_count` and Task 6 `test_ghostwriters_call_holds_its_limits`.

## Calls this plan makes (design; revisit with a stated reason)

- **Confinement lives in the store.**
  - `Principal.confined` is set for a caller of the MCP door with workspace files. It makes `Store._locate` answer `NotFound` for every path outside the request's chat, a `PathError` of `resolve` included.
  - That binds every path-taking tool (through `store.get`) and file route (through `open_file`, `list_dir`, `add_upload`) in one place.
  - The tools that take no path (`list_files`, `search_files`, `run_python`, `write_table`, `write_document`) work on `p.chat_id` already.
- **Ghostwriter's chat is never `default`.** A missing `X-Session-Id`, or `default`, is `invalid session` on every route of Ghostwriter: 400 on REST, `-32600` on MCP. The contract says so for the chat delete; this plan applies it everywhere, so no Ghostwriter file can land in a shared `default` folder.
- **The adapters call the route functions.**
  - One generic adapter per tool passes each parameter by its name (`body`, `p`, `settings`, `store`, `audit`, `jobs`), so both doors run the same code.
  - Three of those values are swapped: a bound audit log, `CallJobs`, and a settings copy.
  - `list_files` takes no body; on MCP it takes `NoArguments`.
- **Time for the previews.**
  - A workspace job on MCP keeps its wall (`CallLimits.wall_s`), but its runner's budget comes from `wall - PREVIEW_RESERVE_S` (5 s).
  - A job's previews take at most `PREVIEW_TOTAL_S` (2 s).
  - So Ghostwriter's wall is at least 10 (`MIN_GHOSTWRITER_WALL_S`).
- **Previews are asked for.** Only `CallJobs` sets `JobRequest.previews`. Open WebUI's and docint's jobs read no preview, and their `spec.json` gains only `"previews": false`.
- **The preview is read in the job's own process**, after its runner, never by the root supervisor. So `run_python`'s code could forge the preview of its own file; the api checks only the shape and the caps (`TablePreview`). This goes into `docs/sandbox.md` as one residual-risk line.
- **The text block leaves the previews out.** On the MCP door, `content[0].text` is the structured answer without `outputs[].preview`. A model fed the text does not get table rows it never asked for. The cards read `structuredContent`. docint's text block is unchanged.
- **Late outputs.**
  - The chat delete removes the chat's job rows.
  - `register_output` refuses an output whose job row is gone. It checks under the store's lock, which the delete holds too.
  - There is no tombstone table.
- **The purpose rule.**
  - On the MCP door it covers every recorded workspace tool, by that tool's own action.
  - It also covers Ghostwriter's file routes, which answer `428`.
  - Compose's default gains `modify` and `collect`, so every recorded Ghostwriter tool and the upload require one.
  - `delete` stays out of the default, so Ghostwriter's retention can delete a chat without one.
  - The terminal door stays without a purpose.
- **The upload's `id`** is in Ghostwriter's answer only. Open WebUI's answer stays `{path, size}`.
- **Discovery per form.** `server/discover` gives an inline caller v0.2.0's `INSTRUCTIONS` and a workspace caller `WORKSPACE_INSTRUCTIONS`.
- **An empty chat delete** writes its event too, with count 0.

    - `PREVIEW_SUFFIXES: Final = (".csv", ".xlsx")`, `PREVIEW_TOTAL_S: Final = 2.0`, `PREVIEW_COUNT_MAX: Final = 100_000`, `PREVIEWS_FILE: Final = "previews.json"`.
    - `table_preview(path: Path, deadline: float) -> TablePreview | None`. Its rows:
      - `columns` is the first record of a csv, or the first row with content of an xlsx's first sheet in workbook order.
      - `rows` are the next records or rows, at most 5.
      - Each row and the header are cut to 20 cells, and each cell to 100 characters.
      - `truncated` is true when anything was left out: rows, columns or characters.
      - `row_count` counts the data rows below the header when the end is reached within `PREVIEW_COUNT_MAX` rows and before `deadline`; otherwise it is `None`.
      - A file that cannot be read, or whose header and rows are not read by `deadline`, gives `None`.
      - An empty file gives `TablePreview(columns=[], rows=[], row_count=0, truncated=False)`.
      - A csv is read as UTF-8, with a BOM dropped and bad bytes replaced. Its delimiter is sniffed among `,`, `;` and tab in the first 8 KiB, with `,` as the fallback.
    - `previews_of(out_dir: Path, deadline: float) -> dict[str, TablePreview]`: the regular files directly in `out_dir` whose suffix, lower-cased, is in `PREVIEW_SUFFIXES`, in name order, while `deadline` holds. A file whose preview is `None` is left out.

## Contract notes

1. **`X-Session-Id` is required, everywhere.** A missing session or `default` is refused for Ghostwriter on every route, not only on `DELETE /files/chat`: 400 `invalid session` on REST, `-32600` on MCP. Ghostwriter always sends its HMAC, so nothing changes for it.
2. **The purpose goes on the file routes too.** Ghostwriter must send `X-Audit-Purpose` and `X-Request-ID` on `/files/upload`, `/files/view` and `/files/chat`, not only on `/mcp`. A required purpose that is missing answers `428 {"detail": "a stated purpose is required"}` there. compose's default now requires one for `modify` and `collect` too, but not for `delete`.
3. **The text block carries no previews.** On the MCP door, `content[0].text` is `structuredContent` without `outputs[].preview`. Ghostwriter gives the model the text and builds its cards from `structuredContent`.
4. **A preview can be `null`** for a csv or xlsx output too: when the file cannot be read, when the header is not read within 2 s, or past 256 KiB of previews in one call. `row_count` counts the data rows below the header and is `null` when they were not counted to the end.
5. **The env-sync tags follow the contract amendment.** Task 8 writes `# [secret] [shared: ghostwriter WORKBENCH_API_KEY]` over the commented `# GHOSTWRITER_WORKBENCH_KEY=`, and `[shared: open-webui-service, ghostwriter]` over `WORKBENCH_RETENTION_DAYS`. T5 names the partners in table order, so the tag holds only while deploy's `workbench-period` lists open-webui-service before the ghostwriter.
6. **`/healthz` and `/metrics`** stay open to every caller, as in v0.2.0, so "the `ghostwriter` key reaches only …" holds for keyed paths. A busy queue on `/mcp` comes back as an `isError` result with `queue_full`, `wait_timeout` or `executor_busy`; Ghostwriter's loop may retry those.
