# The assistant: federation side Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ready the federation for the assistant, the new chat app that replaces Open WebUI: env-sync rows and ADR 0007, the verifier's emitter and scrape target, the gateway route and tile, the lifecycle wiring, and the workspace map, plus two pending v2 follow-ups (D2, L1).

**Architecture:** No service code. Each of Tasks 1-5 is one branch and PR in one repo; Task 6 is a local file with no PR. The order is the spec's §7 with one addition. Task 1 goes first, because rule T5 needs the rows before any member carries a tag. Task 2 follows it. Task 3 merges before the assistant ships. Tasks 4 and 5 wait for assistant v0.1.0. Task 6a can run now; 6b waits for the assistant's merge. Task 5 is a second deploy PR because `make up`, `make clone`, `make pull` and `make setup` loop over `APP_DIRS` and run `make -C` on each entry, so it must not list a directory that does not exist yet.

**Tech Stack:** Make, Docker Compose, Caddyfile, bash, stdlib Python `unittest` (deploy), pytest (obs-plane), Markdown.

**Spec:** `docs/superpowers/specs/2026-11-16-assistant-design.md` (§6.1, §6.5, §7, §9). Siblings written with it: the workbench v0.3.0 plan and the assistant app plan.

## Global Constraints

- **From the shared contract, verbatim:**
  - **Compose:** the project is `name: assistant`, with the services `backend` and `frontend`.
  - **Audit:** the emitter is `assistant` / `backend`, and every event's `service` is `assistant`.
  - **Network aliases:** `assistant-backend` on `inference-net` and on `workbench-net`; `assistant-frontend` on `edge-net`. The frontend is on edge-net only. The backend is never on edge-net or data-net.
  - **Ports:** the backend listens on 8000 (`/api/...`, `/metrics`) and the frontend's nginx on 8080.
  - **Storage:** the external volume `assistant-data`, mounted at `/var/lib/assistant`.
  - **Edge:** the route is `/assistant/` on `:443`. The app's nginx strips the prefix, and the SPA's Vite `base` is `/assistant/`.
  - **Keys:** `ASSISTANT_WORKBENCH_KEY`. Empty means the caller is off. A set key must be at least 32 characters and differ from the other callers' keys. `WORKBENCH_API_KEY` (the same value as workbench's `ASSISTANT_WORKBENCH_KEY`, generated by env-sync); `WORKBENCH_RETENTION_DAYS` (default 7, the same value as workbench's, shared by env-sync); `ASSISTANT_EDGE_SECRET` (shared with edge-plane, generated, at least 32 characters); `OPENAI_API_KEY` (shared with vllm-service, as translator does); `ASSISTANT_CHAT_RETENTION_DAYS` (default 90; `off` only for development); `AUDIT_REQUIRE_PURPOSE` (default empty).
  - **Versions:** workbench 0.2.0 → 0.3.0; assistant 0.1.0 (new repo `nos-tromo/assistant`). deploy, obs-plane, edge-plane: next minor.
  - **Order:** 1. deploy env-sync rows and ADR 0007; 2. obs-plane; 3. workbench v0.3.0; 4. assistant v0.1.0; 5. edge-plane; 6. deploy's lifecycle wiring (`APP_DIRS`, `copy-bundles.sh`, tech-stack) once the assistant repo exists; 7. the `infra/CLAUDE.md` map.
- **Rows**, verbatim from the spec (§6.5). Two groups are new; two rows join existing groups, each placed last in its group.
  ```
  assistant-edge           edge-plane  ASSISTANT_EDGE_SECRET    gen
  assistant-edge           assistant   ASSISTANT_EDGE_SECRET    gen
  workbench-assistant-key  workbench   ASSISTANT_WORKBENCH_KEY  gen
  workbench-assistant-key  assistant   WORKBENCH_API_KEY        gen
  router-key               assistant   OPENAI_API_KEY
  workbench-period         assistant   WORKBENCH_RETENTION_DAYS
  ```
- **Tags the members must carry** (rule T5, checked in Task 1): edge-plane `ASSISTANT_EDGE_SECRET` `[secret] [shared: assistant]`; assistant `ASSISTANT_EDGE_SECRET` `[secret] [shared: edge-plane]`; workbench `ASSISTANT_WORKBENCH_KEY` `[secret] [shared: assistant WORKBENCH_API_KEY]`; assistant `WORKBENCH_API_KEY` `[secret] [shared: workbench ASSISTANT_WORKBENCH_KEY]`; assistant `OPENAI_API_KEY` `[required] [secret] [shared: vllm-service]`; assistant `WORKBENCH_RETENTION_DAYS` `[shared: workbench]`. A source names every other row in table order, so two existing tags change: vllm-service `OPENAI_API_KEY` ends `..., open-webui-service, assistant]` (Task 2) and workbench `WORKBENCH_RETENTION_DAYS` becomes `[shared: open-webui-service, assistant]` (workbench's v0.3.0 PR).
- **Optional or required** (rule X2: the rows of a group agree): the edge secret and the workbench key are optional in edge-plane and workbench, so they are commented and not `[required]` in the assistant's example, even though its backend refuses to start without a 32-character edge secret. `OPENAI_API_KEY` is `[required]` like every app's.
- **Versions:** deploy 0.10.0 → 0.11.0 (Task 1) → 0.12.0 (Task 5); vllm-service 0.11.0 → 0.11.1 (Task 2, a comment); obs-plane 0.14.0 → 0.15.0; edge-plane 0.16.0 → 0.17.0. The bump is in the PR; the `release-tag` workflow mints the tag on merge; never tag by hand.
- **Each repo's rules:** branch plus PR, never commit to `main`; single non-compound `gh` commands; synthetic data only; no developer paths (`/Users/...`, `/home/...`) in anything git sees; `Edit`, never `Write`, on existing test files; confirm CI ran on the last push with `gh pr checks`. Approval of this plan is the approval the repos' `CLAUDE.md` files ask for before editing.
- **Docs stay proportionate:** short additions to existing pages; ADR 0007 follows 0006's sections briefly.
